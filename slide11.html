Phased rollout approach

Launch property websites first, validate the booking flow, train staff, and then connect the group website with a unified booking calendar.

Recommended rollout sequence

This sequence minimizes dependencies and ensures the system is proven before changes are made to the main website.

1
Create all property websites Each hotel gets a live, bookable property site with direct booking enabled.
Independent rollout Fast execution
2
Make them live (soft launch) Confirm booking flow, payments, and confirmations are working correctly.
Validation first Low risk
3
Train staff on the admin panel Short training so reservations and front desk can manage bookings confidently.
Simple SOP 15–30 mins
4
Add booking calendar to the main website Once property sites are stable, we embed the calendar and CTAs on the Legend group site. Requires main site access (or coordination with your web/CMS team).
Requires main site access Unified entry point
Main site access: Access to the Legend group website (or CMS) is required to place the booking calendar and booking entry points correctly.

Prerequisites for full performance

To enable competitive pricing and parity features, RateMatch relies on active OTA listings.

Required

  • Each property listed on Booking.com or Agoda
  • Listings kept updated with rates and availability
PriceMatch enabled Parity confidence

Properties without OTA listings can still go live, but parity comparison and competitive pricing signals will be limited.

Operational clarity

  • Existing OTA management processes remain unchanged
  • Manual / walk-in bookings continue as usual
Decision point: If some properties are not yet on Booking.com or Agoda, those should be prioritized first to unlock the full value of RateMatch.
